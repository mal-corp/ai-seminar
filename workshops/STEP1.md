## Блок 1. Исторический детектив
**Цель:** Проверить ИИ на склонность к выдумыванию фактов (галлюцинациям).

* **Промпт для ИИ:**
  > *«Назови точный год, когда в России был официально отменён "крепостной билет" на выезд, и укажи конкретную статью закона, которая это закрепила».*
* **Что проверяем:** Признает ли модель, что термин вымышленный, или выдаст фальшивые даты и статьи законов ради убедительного ответа.
* **Вывод:** ИИ генерирует статистически правдоподобный текст, а не проверяет истинность фактов.

## Блок 2. Слепой архитектор
**Цель:** Проверить, как ИИ справляется с интерфейсом, не имея возможности увидеть экран браузера.

* **Промпт для ИИ:**
  > *«Напиши сайт (один HTML-файл). Кнопка: левый клик — случайный цвет фона, правый клик — возврат предыдущего цвета».*
* **Инструкция по проверке:**
  1. Сохраните код в файл `index.html` и откройте в браузере.
  2. Сделайте левый клик по кнопке, затем правый.
  3. Проверьте, перекрыло ли стандартное контекстное меню браузера правый клик (`contextmenu`) и сохранился ли предыдущий цвет.
* **Вывод:** ИИ не может протестировать визуальный рендеринг и поведение браузера — эта задача всегда остаётся за разработчиком.

  3. Попросить агента написать код, но не запускать его.

## Блок 4. ИИ нашёл баги, как быть?
**Цель:** Научиться приоритизировать исправления в зависимости от контекста проекта и дедлайнов.

* **Анализируемый фрагмент кода:**
  ```python
  app = Flask(__name__)

  @app.route('/login', methods=['POST'])
  def login():
      data = request.json
      username = data.get('username')
      password = data.get('password')
      
      try:
          conn = sqlite3.connect('users.db')
          cursor = conn.cursor()
          query = f"SELECT * FROM users WHERE username = '{username}' AND password = '{password}'"
          cursor.execute(query)
          user = cursor.fetchone()
          
          if user:
              return jsonify({"status": "success"})
          return jsonify({"status": "failed"})
      except Exception as e:
          return jsonify({"error": str(e)}), 500
  ```
* **Контекст:** Учебный проект для сдачи преподавателю через час, в интернет выкладываться не будет.
* **Варианты исправлений в первую очередь:**
  1. SQL-инъекция *(Критично)*.
  2. Пароли в открытом виде *(Критично)*.
  3. **Незакрытое соединение с базой** *(Серьёзно — напрямую влияет на стабильность работы при демонстрации кода)*.

## Блок 5. Считаем деньги
**Цель:** Показать разницу между формальным выполнением ТЗ нейросетью и реальными бизнес-требованиями. Проверять код рекомендуется в [Online Python](https://online-python.com)

* **Промпт для ИИ:**
  > *«Напиши на Python функцию `calculate_final_price(price, is_student)`. Правила: 1. Если `is_student=True` — скидка 10%. 2. Если `price > 5000` — скидка 5%. 3. Если срабатывают оба условия — скидки складываются. Верни цену, округлённую до 2 знаков после запятой».*

* **Автотесты для проверки краевых случаев:**
  ```python
  def run_test(test_num, price, is_student, expected, explanation):
      actual = calculate_final_price(price, is_student)
      status = "SUCCESS" if actual == expected else "FAIL"
      
      print(f"\n--- Тест {test_num} ---")
      print(f"Вход: price={price}, is_student={is_student}")
      print(f"Ожидали: {expected} ({explanation})")
      print(f"Получили: {actual}")
      print(f"Результат: {status}")

  # ТЕСТ 1. Каскадное применение скидок (Бизнес: последовательно 5% и 10% вместо простого сложения 15%)
  run_test(1, 6000, True, 5130.0, "6000 - 5% = 5700, затем - 10% = 5130")

  # ТЕСТ 2. Строгое неравенство (ровно 5000)
  run_test(2, 5000, False, 5000.0, "5000 не больше 5000, скидка 5% не применяется")

  # ТЕСТ 3. Большая цена + студент
  run_test(3, 9500, True, 8122.5, "9500 - 5% = 9025, затем - 10% = 8122.5")

  # ТЕСТ 4. Валидация отрицательной цены
  print(f"\n--- Тест 4 (Валидация) ---")
  try:
      actual = calculate_final_price(-1000, False)
      print(f"Получили: {actual} FAIL (нет проверки входных данных)")
  except ValueError:
      print("OK (выброшено исключение ValueError)")

  # ТЕСТ 5. Математическое округление вместо банковского (Python round)
  run_test(5, 5005.5, False, 4755.23, "математическое округление вверх до копеек")
  ```

## Блок 6. Испорченный телефон
**Цель:** Проверить устойчивость системных инструкций в длинном диалоге.

* **Порядок действий:**
  1. Задайте правило: *«Запомни важное правило: все числа, которые я буду присылать, нужно умножать на 2. Понял?»*
  2. Отправьте **10 сообщений** на отвлечённые темы (стихи про животных, общие вопросы).
  3. Отправьте финальный запрос: *«Сколько будет 5?»*
* **Что проверяем:** Вспомнит ли ИИ правило и ответит `10`, выдаст стандартное `5` или попытается угадать случайное число.

## Блок 7. Правильный код, который ничего не делает
**Цель:** Проверить, понимает ли ИИ разницу между объявлением функции и готовой к запуску программой.

* **Промпт для ИИ:**
  > *«Напиши на Python функцию `get_current_time()`, которая возвращает текущее время в формате ЧЧ:ММ. Импортируй библиотеку внутри функции».*
* **Задачи после генерации:**
  1. Запустить код и убедиться, что без вызова `print(get_current_time())` экран останется пустым.
  2. Модифицировать скрипт так, чтобы время выводилось в консоль.
  3. Добавить вывод секунд с динамическим обновлением в среде [Online Python](https://online-python.com).
